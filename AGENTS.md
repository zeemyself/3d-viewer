# Repository Guidelines

## Project Structure & Module Organization
Core app code lives in `src/`.
- `src/main.tsx`: app bootstrap and router wiring.
- `src/routes/`: TanStack file routes (currently `__root.tsx` and `index.tsx`).
- `src/components/`: UI and viewer components (`Viewer3D`, panels, selectors).
- `src/lib/`: model domain logic (format loaders, geometry helpers, shared types).
- `src/routeTree.gen.ts`: generated by TanStack Router; do not edit manually.

Static files are in `public/` and importable assets in `src/assets/`. Production output is written to `dist/`.

## Build, Test, and Development Commands
Use Bun for local development (lockfile: `bun.lock`).
- `bun install`: install dependencies.
- `bun run dev`: start Vite dev server with HMR.
- `bun run build`: run TypeScript build checks (`tsc -b`) and create production bundle.
- `bun run preview`: serve the built app locally.
- `bun run lint` / `bun run lint:fix`: run or auto-fix `oxlint` issues.
- `bun run fmt` / `bun run fmt:check`: format or check formatting with `oxfmt`.

## Coding Style & Naming Conventions
TypeScript strict mode is enabled; resolve unused locals/params and avoid loose typing.
- Formatting is enforced by `oxfmt`: 2-space indent, single quotes, no semicolons, trailing commas.
- Components and exported types use PascalCase (`ModelInfoPanel`, `LoadedModel`).
- Variables, functions, and hooks use camelCase (`handleVisibilityChange`, `detectFormat`).
- Keep route filenames aligned with URL paths in `src/routes/`.

## Testing Guidelines
There is no automated test suite configured yet.
- Minimum pre-PR checks: `bun run build`, `bun run lint`, `bun run fmt:check`.
- Validate changes manually in `bun run dev`, including `.stl`, `.obj`, and `.3mf` upload flows.
- If adding tests, use `*.test.ts` / `*.test.tsx` naming near related source or under `src/__tests__/`.

## Commit & Pull Request Guidelines
Git history is concise and mostly Conventional Commit style (example: `feat: add 3D model loading...`).
- Prefer `type(scope): summary` (example: `fix(loaders): handle empty object list`).
- Keep commits focused and imperative.
- PRs should include: short description, linked issue (if any), manual verification steps, and screenshots/GIFs for UI changes.
